In-class Activity 15: Pivoting Lake Superior Ice Data

Today’s Objectives

  1. Read a messy, wide government text file directly from the web
  2. Say why wide data breaks ggplot() and group_by()
  3. Use pivot_longer() to make it tidy — and pivot_wider() to make a summary table
  4. Fix a real-world date wrinkle: winters that cross the new year
  5. Regress one month’s ice cover on year to get a slope
  6. Rebuild NOAA’s “spaghetti plot” of every ice season
  7. Use slice_max() to pull each winter’s peak ice cover
  8. Fit lm() to ask whether maximum ice cover is declining
  9. Flip the summary table back to long and compare every month’s slope at once
  10. If there is time: join in Duluth’s monthly temperature and regress ice on temp — this month’s and last month’s
  11. Repeat the whole thing on a different Great Lake, for homework

Note🔮 Predict before you run

Pivoting is easy to fake your way through by staring at dim() after the fact. Before each pivot, say out loud the shape you expect — how many rows, how many columns — then run it. A wrong prediction points straight at the argument you misunderstood: cols, names_to, or values_to.

Keep the plots plain today — no labels, colors, or themes except where the code already has them. The goal is to read them.

🧩 Chunk 1 — Why wide data is a problem (after lecture Chunk 1)

Parts 1–2: read NOAA’s raw file and inspect its wide shape.

Part 1 · Load libraries and read the raw file

▶ Run this:

# Load libraries ---------------------------------------
library(tidyverse)   # dplyr + tidyr + ggplot2 + stringr
library(lubridate)   # ymd(), month(), update()

▶ Run this:

# Read NOAA's messy text file straight off the web -----
url <- "https://www.glerl.noaa.gov/data/ice/glicd/daily/sup.txt"

ice_raw <- read.table(
  url,
  header = TRUE,
  na.strings = c("-999", "-99.00", "NA")
) %>%
  rownames_to_column(var = "date") %>%
  as_tibble()

head(ice_raw)

⚠️ Watch out! This file is space-separated, not comma-separated — that is why it needs read.table() and not read_csv(). The day labels (Nov-10…) arrive as row names, so rownames_to_column() turns them into a real date column.

🧩 Chunk 2 — Reshape with pivot_longer & fix dates (after lecture Chunk 2)

Parts 3–4: pivot the data long, then fix the winters that cross the new year.

Part 3 · Pivot from wide to long

🔮 Predict first: ice_raw is about 209 rows × 55 columns. After pivot_longer() collapses every year column, how many columns will the result have, and roughly how many rows?

▶ Run this:

# Collapse every year column into year + ice_cover -----
ice_long <- ice_raw %>%
  pivot_longer(
    cols = -date,
    names_to = "year",
    names_prefix = "X",
    values_to = "ice_cover"
  ) %>%
  arrange(year, date)

dim(ice_long)

head(ice_long)

Four arguments do all the work: cols = -date pivots everything except date, names_to says where the old column names go, names_prefix strips the X off the front, and values_to names the column the cell values land in.

✏️ Q5: Rows and columns in ice_long. Was your prediction close?

✏️ Q6: What does names_prefix = "X" do? What would the year column hold if you left it out?

Part 4 · Fix winters that cross the new year

An ice season runs Nov → May, but NOAA labels the whole season by the year it ends in. So Nov-10 under column 1974 really happened in November 1973.

▶ Run this:

# Nov/Dec belong to the PREVIOUS calendar year ---------
ice_clean <- ice_long %>%
  mutate(
    year = as.numeric(year),
    calendar_year = if_else(
      str_starts(date, "Nov|Dec"),
      year - 1,
      year
    ),
    full_date = ymd(paste(calendar_year, date, sep = "-")),
    month = month(full_date, label = TRUE)
  ) %>%
  drop_na(ice_cover, full_date)

dim(ice_clean)

head(ice_clean)

⚠️ Watch out! ymd() will warn that about 41 dates “failed to parse”. Those are Feb-29 in years that had no February 29th. drop_na() removes them, which is exactly right — there was no such day.

✏️ Q7: Explain the if_else() in plain English: the condition tested, what happens when it is TRUE, and why we subtract 1 from year.

✏️ Q8: How many rows did drop_na() remove, and what were they? (Compare nrow(ice_long) and nrow(ice_clean).)

🧩 Chunk 3 — Summarize & pivot back wider (after lecture Chunk 3)

Parts 5–7: summarize the tidy data, rebuild a readable table with pivot_wider(), and regress one month on year.

Part 5 · Summarize now that we’re long

▶ Run this:

# Mean ice cover for every year-month ------------------
monthly_avg <- ice_clean %>%
  group_by(year, month) %>%
  summarize(
    mean_ice = mean(ice_cover, na.rm = TRUE),
    .groups = "drop"
  )

head(monthly_avg)

✏️ Q9: This is the same pattern you used in Summary Statistics. Why was it impossible to run on ice_raw?

Part 6 · Pivot back to a wide summary table

🔮 Predict first: pivot_wider() will make one row per year and one column per month. Roughly how many rows (years) and columns (months + 1)?

▶ Run this:

# One row per year, one column per month ---------------
ice_pivot_table <- ice_clean %>%
  pivot_wider(
    id_cols = year,
    names_from = month,
    values_from = ice_cover,
    values_fn = mean
  ) %>%
  arrange(year)

ice_pivot_table

⚠️ Watch out! The month columns come out in the order the months first appear in the data, not in calendar order — Apr, Dec, Feb, Jan… That is normal for pivot_wider(), and it is why long data is better for computing.

✏️ Q10: Rows and columns in the table. Was your prediction close? Why is a Jun column there, and why is it almost all NA?

✏️ Q11: When would you reach for pivot_longer(), and when for pivot_wider()? One sentence each.

💡 Key idea: long is for computing — group_by, summarize, ggplot. Wide is for reading — a table a human scans. The same data, shaped for two different audiences.

Part 7 · Regress one month’s ice cover on year

February is usually Lake Superior’s iciest month. Now that the wide table has a Feb column, one month’s whole 50-year history is a single column — so a regression on year is one line of code.

🔮 Predict first: is February ice cover declining, flat, or rising? Will the slope be significant at α = 0.05?

▶ Run this:

# February ice cover predicted by year -----------------
feb_model <- lm(Feb ~ year, data = ice_pivot_table)

summary(feb_model)

▶ Run this:

# Plot it ----------------------------------------------
ice_pivot_table %>%
  ggplot(aes(x = year, y = Feb)) +
  geom_point() +
  geom_smooth(method = "lm")

✏️ Q12: Slope (% per year), p-value, and R² for February. Significant at α = 0.05?

✏️ Q13: Try lm(Mar ~ year, ...) and lm(Apr ~ year, ...). Does every month have the same slope? Which month is losing ice fastest?

💡 Key idea: this works because the wide table put one month in one column. Doing it month by month gets old fast — in Part 10 you flip the table back to long and get every month’s slope in one shot.

🧩 Chunk 4 — Visualize & model the trend (after lecture Chunk 4)

Parts 8–11: rebuild NOAA’s spaghetti plot, pull each year’s peak, model the trend, flip the table back to long, and — if there is time — join in Duluth’s temperature.

Part 8 · Rebuild NOAA’s spaghetti plot

This is the long one. Type it, run it, and read it — do not worry about memorizing it.

The one idea worth carrying away: to overlay 50 winters on one axis, every date is forced onto a single fake year — October onward becomes 1999, January onward becomes 2000 — so the x-axis runs November → June once.

▶ Run this:

# Force every date onto one fake shared year -----------
ice_plot_data <- ice_clean %>%
  mutate(
    plot_date = if_else(
      month(full_date) >= 10,
      update(full_date, year = 1999),
      update(full_date, year = 2000)
    )
  )

# The historical average for each day-of-winter --------
historical_avg <- ice_plot_data %>%
  group_by(plot_date) %>%
  summarize(avg_ice = mean(ice_cover, na.rm = TRUE))

current_yr <- max(ice_plot_data$year)
past_years <- ice_plot_data %>% filter(year < current_yr)
current_year_data <- ice_plot_data %>% filter(year == current_yr)

▶ Run this:

# Three layers, three geom_line() calls ----------------
ice_spaghetti_plot <- ggplot() +
  geom_line(
    data = past_years,
    aes(x = plot_date, y = ice_cover, group = year),
    color = "blue",
    alpha = 0.15
  ) +
  geom_line(
    data = historical_avg,
    aes(x = plot_date, y = avg_ice),
    color = "red",
    linewidth = 1.2
  ) +
  geom_line(
    data = current_year_data,
    aes(x = plot_date, y = ice_cover),
    color = "black",
    linewidth = 1.2
  ) +
  scale_x_date(date_labels = "%b", date_breaks = "1 month") +
  labs(
    title = "Lake Superior Average Ice Cover",
    subtitle = paste("Comparing", current_yr, "to Historical Data"),
    x = NULL,
    y = "Ice Cover (%)"
  ) +
  theme_bw()

ice_spaghetti_plot

Reporting the slope without the R² — or the R² without the slope — tells only half of that.

Part 10 · Flip the wide table back to long (you write this one)

This is the one chunk the skeleton leaves blank — this is where we left off in class. You have the pattern from Part 3; the only thing that changes is which table you pivot.

In Part 7 you ran one regression per month, by hand, one column at a time. There is a better way: flip ice_pivot_table back to long and every month’s slope comes out of a single group_by().

🔮 Predict first: ice_pivot_table is about 54 rows × 9 columns. Pivot all the month columns long — how many rows before you drop the NAs?

▶ Type this yourself:

# Wide summary table -> long again ---------------------
monthly_long <- ice_pivot_table %>%

    cols = -year,

Part 11 · If there is time — bring in Duluth’s temperature

Ice cover is the response to something: cold. So far every model has used year as the predictor, which is a stand-in for “whatever is changing.” Now use the actual driver.

You need the temperature data on the same scale as the ice data — one value per calendar month — and then a left_join() to put the two together. (That join is next week’s lecture. Here it is as a preview.)

▶ Run this:

# Two more libraries -----------------------------------
library(janitor)   # clean_names()
library(GSODR)     # NOAA station data

You installed GSODR back in Activity 12 — no need to install it again. Loading it prints a notice that GSOD retired in Aug 2025; that is expected, the archive still downloads.

▶ Run this:

# Mean ice cover for each calendar month ---------------
ice_monthly <- ice_clean %>%
  mutate(month_date = floor_date(full_date, "month")) %>%
  group_by(month_date) %>%
  summarize(mean_ice = mean(ice_cover, na.rm = TRUE),
            .groups = "drop")

ice_monthly

floor_date() knocks every date back to the first of its month, so every day in February 1979 becomes 1979-02-01. That gives you one row per month, with a real date as the key to join on.

⚠️ Watch out! Group on month_date, not on year and month. Remember year is the season-end year — a December belongs to the season labeled with the next year. floor_date(full_date) uses the real calendar date, which is what the weather data will be keyed on.

▶ Run this:

# Duluth daily weather, same years as the ice record ---
duluth_df <- get_GSOD(years = 1973:2025,
                      station = "727450-14913") %>%
  clean_names()

dim(duluth_df)

This takes a minute — it is 50+ years of daily records.

▶ Run this:

# Monthly mean temp, plus the PREVIOUS month's temp ----
dlh_month <- duluth_df %>%
  group_by(year, month) %>%
  summarize(mean_temp = mean(temp, na.rm = TRUE),
            .groups = "drop") %>%
  mutate(month_date = ymd(paste(year, month, "01", sep = "-"))) %>%
  arrange(month_date) %>%
  mutate(temp_prior = lag(mean_temp))

head(dlh_month)

lag() shifts a column down by one row — so temp_prior on the February row holds January’s temperature. It only works if the rows are in order and no months are missing, which is why arrange(month_date) comes first.

✏️ Q24: Look at the first row of dlh_month. Why is temp_prior NA there?

▶ Run this:

# Join the temperature onto the ice data ---------------
ice_temp_df <- ice_monthly %>%
  left_join(dlh_month, by = "month_date")

ice_temp_df %>%
  select(month_date, mean_ice, mean_temp, temp_prior)

✏️ Q25: ice_monthly had about 322 rows. How many does ice_temp_df have? What does that tell you about what a left_join() does to row count?

✏️ Q26: A few rows have NA for mean_temp. Which months, and why? (Think about where each record starts and stops.)

✏️ Q28: Which predictor won, and by how much? Was your prediction right?

✏️ Q29: Why would the previous month’s cold predict today’s ice better than today’s cold does? (How long does it take a lake the size of Superior to freeze?)

✏️ Q30: Both slopes are negative. Say what the lag model’s slope means in plain language: one degree colder last month buys you how much more ice this month?

💡 Key idea: this is the whole arc of the course in one place. Pivot the data so it can be grouped, summarize it to the scale your question lives at, join in a second source keyed on something both tables share, then model it. The lag is the science: a lake is a big thermal flywheel, so its state today reflects the weather of weeks past, not the weather of this morning.
