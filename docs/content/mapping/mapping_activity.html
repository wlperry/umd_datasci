In-class Activity 17: Mapping Bigfoot 🦶

NoteAbout the data

The Bigfoot Field Researchers Organization (BFRO) has collected sighting reports for decades. The file is real — these are genuine reports people filed — geocoded to a latitude and longitude. Whether Bigfoot is real is not the point. Where people report seeing one is a real spatial dataset, and it behaves exactly like any occurrence dataset you will map in your own project.

Today’s Objectives

  1. Make latitude/longitude into a spatial sf object
  2. Draw sighting points on a map of US states
  3. Count sightings per state and join them to the map
  4. Shade a choropleth and reproject it for a proper US look
  5. Map a species you pick from GBIF, for homework
Tip📂 Files for today
  • Skeleton script: 17_mapping_skeleton.R → save it as scripts/17_mapping.R.
  • Data file, in your data/ folder:
    • bfro_reports_geocoded.csv — one row per sighting report: latitude, longitude, state, county, season, classification, title, date. (Source: BFRO via Kaggle.)
ImportantWhat you hand in
  • All of today’s code is right here in this activity. Type it into your script as we go and run it chunk by chunk. The skeleton has everything except Part 9 already written — Part 9 is the one blank you fill in yourself.
  • The Q boxes are things to think about, not inline homework. Read them, talk them over, answer them in your head. They are there for your benefit — you do not have to type answers into the script, and they are not graded.
  • The Extension at the bottom maps a species you pick from GBIF — that part you write, and that part is graded.
  • Hand in scripts/17_mapping.R. Run it top to bottom (Ctrl/Cmd + Shift + Enter) first — it must run with no errors.
Note🔮 Predict before you run

Before each map draws, name the region or state you expect to stand out. Then type the code yourself — st_as_sf(), geom_sf(), and coord_sf() all take arguments in a specific order (coords = c("longitude", "latitude"), crs = 4326), and typing them is what keeps that order from slipping the next time you write it from scratch.

TipThe invisible(NULL) lines in the skeleton

Every chunk ends with invisible(NULL). It is a bumper. Press Ctrl/Cmd + Enter on a chunk’s last real line and your cursor jumps to the next line that has code on it — without the bumper, that is the next chunk, way down past the next heading. With it, the cursor stops right there and you keep your place. It does nothing and prints nothing.

🧩 Chunk 1 — Make it spatial (after lecture Chunk 1)

Parts 1–3: load the sightings, clean the coordinates, and build an sf object.

Part 1 · Load libraries and data

▶ Run this:

# Load libraries ---------------------------------------
library(tidyverse)
library(sf)     # spatial data frames
library(maps)   # ready-made state outlines

▶ Run this:

# Read the sighting reports ----------------------------
bigfoot_df <- read_csv("data/bfro_reports_geocoded.csv")

dim(bigfoot_df)

bigfoot_df %>%
  select(title, state, latitude, longitude, classification, season) %>%
  head()

✏️ Q1: Rows and columns in the raw file. What does one row represent?

Part 2 · Clean the coordinates

▶ Run this:

# Drop missing coords + keep the lower 48 --------------
bigfoot_df <- bigfoot_df %>%
  filter(!is.na(latitude), !is.na(longitude)) %>%
  filter(longitude > -125, longitude < -66,
         latitude  >   24, latitude  <  50)

nrow(bigfoot_df)

⚠️ Watch out! Those four numbers are a bounding box — a crude rectangle around the lower 48. It throws away Alaska and Hawaii on purpose, because one Alaskan point stretches the whole map and squashes everything else into a corner.

✏️ Q2: How many rows remain, and how many did you just drop? Why must missing coordinates go before the next step and not after?

Part 3 · Build the sf object

🔮 Predict first: you are about to plot ~4,000 points with no basemap at all. What shape will the cloud of points make?

▶ Run this:

# Turn lon/lat into a geometry column ------------------
bigfoot_sf <- bigfoot_df %>%
  st_as_sf(coords = c("longitude", "latitude"), crs = 4326)

bigfoot_sf

ggplot(bigfoot_sf) +
  geom_sf(alpha = 0.2, size = 0.5)

✏️ Q3: In coords = c("longitude", "latitude"), which comes first — x or y? What happens if you swap them?

✏️ Q4: The points drew a recognizable USA with no map underneath. What does that tell you about what a “map” actually is?

💡 Key idea: an sf object is just a data frame with one extra column — geometry — holding the coordinates. Every dplyr verb you already know still works on it.

🧩 Chunk 2 — Points on a real map (after lecture Chunk 2)

Parts 4–6: add a US basemap and layer the sightings on top.

Part 4 · Get US states as sf

▶ Run this:

# Built-in state outlines -> sf ------------------------
states_sf <- st_as_sf(
  maps::map("state", plot = FALSE, fill = TRUE)
) %>%
  st_set_crs(4326)

nrow(states_sf)

states_sf %>%
  head(3)

✏️ Q5: What is in the ID column, and what case are the state names in? You will need that answer in Part 8.

Part 5 · Layer the sightings on the map

🔮 Predict first: which region will have the densest cluster of points? Commit before you run it.

▶ Run this:

# Basemap first, points on top -------------------------
ggplot() +
  geom_sf(data = states_sf, fill = "grey96", color = "grey75") +
  geom_sf(data = bigfoot_sf, aes(color = classification),
          alpha = 0.3, size = 0.6) +
  theme_void()

✏️ Q6: Was your prediction right? Why does the order of the two geom_sf() layers matter — what would you see if you drew them the other way around?

✏️ Q7: theme_void() strips the grey panel, the gridlines, and the axes. Why is that usually right for a map, when it would be wrong for a scatterplot?

Part 6 · Who is reporting what

▶ Run this:

# The three report classes -----------------------------
bigfoot_df %>%
  count(classification)

Class A is a claimed clear sighting, Class B a less certain one, Class C a second-hand report.

✏️ Q8: Does the geographic pattern look like it is about Bigfoot, or about people — where they live, hike, and file reports? What would you need to tell those two apart?

🧩 Chunk 3 — Choropleth by state (after lecture Chunk 3)

Parts 7–9: count per state, join to the map, shade it.

Part 7 · Count sightings per state

🔮 Predict first: which state has the most reports? Commit before you run count().

▶ Run this:

# Sightings per state, lowercased to match the map -----
sightings_by_state <- bigfoot_df %>%
  mutate(state = str_to_lower(state)) %>%
  count(state, name = "sightings") %>%
  arrange(desc(sightings))

head(sightings_by_state)

✏️ Q9: The top three states. Why do we lowercase the state names now, before the join, instead of fixing it afterwards?

Part 8 · Join counts to the map

This is last class’s joins lecture, pointed at a map. The polygons are one table, the counts are another, and state is the key.

▶ Run this:

# Join sightings onto the state polygons ---------------
states_map <- states_sf %>%
  mutate(state = str_remove(ID, ":.*")) %>%   # drop ":north" etc.
  left_join(sightings_by_state, by = "state")

states_map %>%
  st_drop_geometry() %>%
  head()

▶ Run this:

# Did every polygon find a count? ----------------------
states_map %>%
  st_drop_geometry() %>%
  filter(is.na(sightings))

Some ID values look like washington:main and washington:whidbey island — one row per landmass, not per state. str_remove(ID, ":.*") cuts everything from the colon on, so every island collapses back to its state name and the key matches.

✏️ Q10: Exactly one polygon came back with NA sightings. Which one, and is that a bug in your join or a true zero? How would you tell the difference?

✏️ Q11: What would the map look like if you had not lowercased the state names before joining? Say it out loud before you try it.

Part 9 · Shade the choropleth (you write this one)

This is the one chunk the skeleton leaves blank — this is where we left off in class. Everything you need is in Part 8’s result; what changes is that you now map sightings to a fill.

🔮 Predict first: the darkest state should be your Part 7 answer. Will the second-darkest be a state with lots of forest, or a state with lots of people?

▶ Type this yourself:

# The map IS the bar chart -----------------------------
ggplot(states_map) +
  geom_sf(aes(fill = sightings), color = "white") +
  scale_fill_viridis_c(option = "magma", direction = -1) +
  theme_void()

direction = -1 flips the scale so that more sightings = darker. Left at the default, the states with the most reports come out palest, which reads backwards to almost everyone.

✏️ Q12: Does the darkest state match your Part 7 prediction? Name one state that surprised you.

✏️ Q13: The state with the NA from Part 8 is drawn in grey. Is grey the honest color for “no reports,” or does it hide something?

✏️ Q14: Washington and California have many sightings — but they are also big, populous, and heavily forested. What extra data would you need to make this a fair state-to-state comparison?

💡 Key idea: the choropleth recipe never changes with the dataset — get polygons, get counts, left_join() them on a matching key, shade with geom_sf(aes(fill = ...)). Learn the four steps once and every occurrence dataset you ever meet maps the same way.

🧩 Chunk 4 — Polish & explore (after lecture Chunk 4)

Parts 10–12: reproject, explore by season, and save.

Part 10 · Reproject for a proper US look

▶ Run this:

# Albers Equal-Area (EPSG:5070) ------------------------
ggplot(states_map) +
  geom_sf(aes(fill = sightings), color = "white") +
  scale_fill_viridis_c(option = "magma", direction = -1) +
  coord_sf(crs = 5070) +
  theme_void()

✏️ Q15: Compare this to your Part 9 map. What changed about the shape of the country? Which states grew and which shrank?

✏️ Q16: 4326 is degrees of latitude and longitude; 5070 is an equal-area projection in meters. Why does an area-based map like a choropleth deserve an equal-area projection?

Part 11 · If there is time — explore by season

🔮 Predict first: which season has the most reported sightings? Why might that be — think about who is outside.

▶ Run this:

# One small map per season -----------------------------
bigfoot_sf %>%
  filter(season %in% c("Spring", "Summer", "Fall", "Winter")) %>%
  ggplot() +
  geom_sf(data = states_sf, fill = "grey96", color = "grey80") +
  geom_sf(alpha = 0.2, size = 0.4, color = "firebrick") +
  facet_wrap(~ season) +
  coord_sf(crs = 5070) +
  theme_void()

The filter() drops reports whose season is recorded as "Unknown" — there are a fair number, and they would draw a fifth panel that means nothing.

✏️ Q17: Which season dominates? Is that about Bigfoot, or about people?

Part 12 · Save your map

▶ Run this:

# Build it once, save it ------------------------------
choropleth_plot <- ggplot(states_map) +
  geom_sf(aes(fill = sightings), color = "white") +
  scale_fill_viridis_c(option = "magma", direction = -1) +
  coord_sf(crs = 5070) +
  labs(title = "Bigfoot Sightings by State",
       fill = "Sightings") +
  theme_void()

ggsave("figures/bigfoot_choropleth.png",
       plot = choropleth_plot,
       width = 7, height = 5, units = "in", dpi = 300)

This is the one plot that gets a labs() title, because it is leaving your screen. A figure that lands in a report needs to say what it is; a figure you are only reading off the Plots pane does not.

✏️ Q18: Open the saved PNG. Does it look like what was in the Plots pane? If the text is tiny, which ggsave() argument would you change?

Extension — out of class (~30–40 min)

Turn this in with your script. In class you mapped Bigfoot reports. Now you map a real species you pick, pulled live from GBIF with rgbif.

Important

E2 and E3 must be handwritten on paper, photographed, and embedded (![caption](my_photo.jpg)). Typed answers get at most half credit, even if correct — E2 is your prediction before you download.

E1 · Map your own species (4 pts)

Pick any species with a scientific name (a plant, bird, mammal, insect — your choice). Then, with the same recipe as class:

library(rgbif)

# 1. up to ~1500 US records that have coordinates
occ <- occ_data(scientificName = "Genus species",
                country = "US", hasCoordinate = TRUE,
                limit = 1500)$data

# 2. keep real coordinates, build the
# sf object (x = longitude first!)
sp_sf <- occ %>%
  filter(!is.na(decimalLongitude), !is.na(decimalLatitude)) %>%
  st_as_sf(coords = c("decimalLongitude", "decimalLatitude"),
           crs = 4326)

# 3. points on the same states basemap you used in class
ggplot() +
  geom_sf(data = states_sf, fill = "grey96", color = "grey80") +
  geom_sf(data = sp_sf, alpha = 0.3, size = 0.6,
          color = "darkgreen") +
  coord_sf(crs = 5070) +
  theme_void()

You will need install.packages("rgbif") the first time. Save the map to figures/ at dpi = 300, and record your species and how many records you got.

E2 · Predict, then check — ✍️ by hand (3 pts)

Before running E1: sketch, on a rough US outline, where you expect your species to occur and why (climate, habitat, range you know). Then run E1 and write 2–3 sentences comparing your prediction to the real map — and note whether anything looks like a sampling artifact rather than real range (a dense blob around one city, a hard line at a state border).

E3 · Explain it — ✍️ by hand (3 pts)

  1. GBIF records are where people reported the species, not where it truly lives. Give one concrete way that could bias your map.
  2. Washington and California had many Bigfoot reports partly because they are big and populous. What extra data would make a state-to-state comparison of your species fair?
  3. The choropleth recipe (polygons → counts → left_join() → geom_sf(fill=)) did not change from Bigfoot to your species. In your own words, why is that recipe dataset-independent?
