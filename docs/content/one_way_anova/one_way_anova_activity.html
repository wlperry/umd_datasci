Part 1 · The question

Do the three penguin species differ in body mass?

  • Y = body_mass_g — numeric response
  • X = species — categorical predictor, 3 levels

One numeric response across the levels of one categorical predictor. That is a one-way ANOVA.

✏️ Q1: Why is this an ANOVA and not a t-test? One sentence.

✏️ Q2: If you ran t-tests on all three pairs of species instead, what would be wrong with that?

Part 2 · Load the libraries and the data

▶ Run this at the top of your script:

library(tidyverse)      # dplyr + ggplot2 + forcats
library(palmerpenguins) # the penguins data
library(car)            # Anova()

▶ Run this:

penguins_df <- penguins %>%
  drop_na(body_mass_g, species)

penguins_df %>% count(species)

⚠️ Watch out! R 4.5 ships its own penguins data set, and its mass column is called body_mass, not body_mass_g. If you forget library(palmerpenguins) you will not get a missing-object error — you get

Error in `drop_na()`: Column `body_mass_g` doesn't exist

The fix is the library() call.

✏️ Q3: Write down the sample size of each species. Are the groups balanced (equal n)?

Part 3 · Plot it before you test it

🔮 Predict first: which species is heaviest? Do you think all three differ, or only one?

▶ Run this:

penguins_df %>%
  ggplot(aes(x = species, y = body_mass_g)) +
  geom_boxplot() +
  geom_jitter(width = 0.15)

✏️ Q4: Describe what you see — the heaviest species, the lightest, whether any two look almost the same, and whether the boxes look like they have the same spread.

Part 4 · species is a factor, and factors have an order

A factor is a categorical column with a fixed, ordered set of levels. ggplot and lm both use that order.

▶ Run this:

class(penguins_df$species)

levels(penguins_df$species)

The stored order is alphabetical — R’s default, not a decision anyone made about penguins. fct_reorder() puts the groups in order of the thing you are testing, and it has to go inside mutate().

▶ Run this:

penguins_df %>%
  mutate(species = fct_reorder(species, body_mass_g,
                               .fun = median)) %>%
  ggplot(aes(x = species, y = body_mass_g)) +
  geom_boxplot()

✏️ Q5: What order were the levels stored in, and what order are they in after fct_reorder()? Here they come out the same — why is it still worth doing?

💡 Key idea: the rest of the fct_* family — rename levels, merge them, lump rare ones — is in Common Code 15 · Factors. Today you need ordering, and the baseline in Part 7.

Part 5 · State the hypotheses

Do this before you fit anything.

✏️ Q6: Write the hypotheses — H₀ in words, Hₐ in words, H₀ in symbols, and your α.

💡 Key idea: Hₐ only says “at least one differs”. It does not say which. Naming the species is the job of the follow-up tests, next lecture.

Part 6 · Fit the model

▶ Run this:

mass_model <- lm(body_mass_g ~ species, data = penguins_df)

Exactly the same lm() call as the regression activity. The only difference is that X is categorical.

Fitting the model and reading a table from it are two separate steps. First look at what lm() did with the factor.

▶ Run this:

coef(mass_model)

(Intercept) is the mean of the first level — Adelie. The other two numbers are differences from Adelie. That is treatment coding, R’s default.

✏️ Q7: From coef(), what is the mean mass of an Adelie? How much heavier is a Gentoo than an Adelie?

Part 7 · Change the baseline with fct_relevel()

🔮 Predict first: if Gentoo becomes the first level, does the overall F / p change, or only the coefficients?

▶ Run this:

penguins_relevel <- penguins_df %>%
  mutate(species = fct_relevel(species, "Gentoo"))

mass_model_gentoo <- lm(body_mass_g ~ species,
                        data = penguins_relevel)

coef(mass_model_gentoo)

✏️ Q8: What does (Intercept) mean in each of the two models? Did the overall ANOVA question change?

💡 Key idea: releveling changes which comparison the coefficients show, not whether any means differ. Use it to make the baseline a group your reader cares about — a control, a reference site.

Part 8 · Read the ANOVA table — three ways

🔮 Predict first: is p nearer 0.5, 0.05, or far below 0.001?

▶ Run this — the classic table:

mass_aov <- aov(body_mass_g ~ species, data = penguins_df)

summary(mass_aov)

▶ Run this — base R anova() on the lm:

anova(mass_model)

That is Type I, which is sequential and therefore order-dependent. With one predictor there is no order to depend on.

▶ Run this — car::Anova():

Anova(mass_model)

That is Type II — the default, and order-independent. This is the one to make a habit of. Anova(mass_model, type = 2) is the same thing spelled out.

Call Package Gives you
aov() + summary() base R the classic ANOVA table
anova(model) base R Type I (sequential)
Anova(model) car Type II (the default)
Anova(model, type = 3) car Type III

⚠️ Watch out! Lowercase anova() and capital Anova() are different functions from different packages. If you see could not find function "Anova", you forgot library(car).

✏️ Q9: From the table — F, both df, and p. Reject H₀ at α = 0.05? Do all three tables agree on F?

Part 9 · Type III, and the contrasts option it needs

Type III sums of squares are only meaningful when the factor is coded against the grand mean (contr.sum), not against a baseline group (contr.treatment). Ask for type = 3 on a treatment-coded model and car will still print a table — it just will not be the test you think it is.

▶ Run this — what is R using right now?

getOption("contrasts")

That is R’s default: treatment coding for unordered factors, polynomial for ordered ones.

▶ Run this — Type III on the treatment-coded model (not right):

Anova(mass_model, type = 3)

▶ Run this — the four-line pattern: set → refit → test → set back:

options(contrasts = c("contr.sum", "contr.poly"))

mass_model_sum <- lm(body_mass_g ~ species, data = penguins_df)

Anova(mass_model_sum, type = 3)

options(contrasts = c("contr.treatment", "contr.poly"))
ImportantThe refit is not optional

A model remembers the coding it was fitted with. Change the option, reuse the old model, and nothing happens at all.

▶ Run this — prove the switch back worked, and that each model carries its own coding:

getOption("contrasts")

mass_model$contrasts

mass_model_sum$contrasts
ImportantWhy you set it back

options() is global and sticky. It stays changed for the rest of your R session and silently affects every model you fit afterwards — including code you wrote weeks ago.

✏️ Q10: Compare the two type = 3 tables. Which row changed, and which row stayed the same? Given that, why does the contrast coding matter at all here? (Hint: it does not — yet. What changes once you have two factors and an interaction?)

Part 10 · Report it

For this course, report Anova(model) — Type II — unless you have a specific reason not to.

▶ Run this:

Anova(mass_model)

✏️ Q11: Write the results sentence with your numbers in it.

Template:
"Body mass differed significantly among the three penguin species
 (one-way ANOVA: F(__, __) = ____, p ____)."

Never write p = 0.000. Write p < 0.001.

✏️ Q12: That sentence does not say which species differ, and it does not say whether the model was allowed to give us that p-value. Which of those two gaps worries you more, and why?
