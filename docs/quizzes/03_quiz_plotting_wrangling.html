Building a plot — ggplot() + aes()

  1. (MC) In leaf_df %>% ggplot(aes(x = shade, y = mass_g)) + geom_boxplot(), what job does aes() do?

    1. Maps data columns to plot properties like position and color

    2. Loads the ggplot2 package

    3. Saves the plot to a file

    4. Filters out rows with missing data

    5. Sorts the boxplots alphabetically

  2. (Predict) What will this code produce?

    leaf_df %>%
  ggplot(aes(x = mass_g, y = thickness_mm)) +
  geom_point()

    1. A boxplot of thickness by shade

    2. A scatterplot with one point per leaf

    3. A bar chart counting leaves

    4. A histogram of mass_g

    5. An error, because geom_point() needs a fill aesthetic

  3. (Fix) This code throws an error. What’s missing?

    leaf_df %>%
  ggplot() +
  geom_point(x = mass_g, y = thickness_mm)

    1. geom_point() doesn’t exist — use geom_dot()

    2. leaf_df needs clean_names() first

    3. x and y must be wrapped in aes(): geom_point(aes(x = mass_g, y = thickness_mm))

    4. You can’t pipe a data frame into ggplot()

    5. mass_g and thickness_mm must be converted to factors first

    True / False

The ylim() trap — zooming vs. deleting data

  1. (Fix) ★ A student adds + ylim(0, 1) to a boxplot of mass_g to “zoom in,” but the median line shifts and looks wrong. What happened?

    1. ylim() cropped the view only, so nothing should have changed — the student misread the plot

    2. ylim() removed rows with mass_g outside 0–1 before the boxplot statistics (median, quartiles) were computed, so the boxplot itself is now wrong

    3. ylim() only works on scatterplots, not boxplots

    4. The student needed xlim() instead

    5. ylim() doubled every value automatically

  2. (MC) To zoom into part of a plot without changing any of the underlying statistics, you should use:

    1. scale_y_continuous(limits = c(...))

    2. ylim(...)

    3. coord_cartesian(ylim = c(...))

    4. filter() before plotting

    5. geom_ylim()

  3. (T/F) scale_y_continuous(limits = c(0, 1)) and ylim(0, 1) both silently drop any row outside that range before the plot’s statistics are calculated.

    True / False

    1. Requires categorical data on the x-axis

    5. Ignores the x aesthetic entirely

    3. Only works inside RStudio, never in a script

    4. Automatically applies a theme to every plot without calling it

filter() and select() — rows and columns

  1. (MC) leaf_df %>% filter(shade == "sunny") keeps:

    1. Only rows where shade equals "sunny"

    2. Only the shade column

    3. Every row, sorted by shade

    4. Only rows where shade is missing

    5. Only columns whose name contains “sunny”

  2. (Fix) This throws We detected a named input. What’s the fix?

    leaf_df %>% filter(shade = "sunny")

    1. filter(shade <- "sunny")

    2. filter(shade == "sunny") — use == to compare, not =

    3. filter("sunny" = shade)

    4. filter(shade = "sunny", strict = FALSE)

    5. filter(shade) and drop "sunny" entirely

  3. (Fix) A student filters with filter(shade == "Sunny") and gets zero rows, even though sunny leaves exist. Why?

    1. filter() only works on numeric columns

    2. You need quotes around shade, not "Sunny"

    3. R is case-sensitive, and the data stores "sunny" in lowercase

    4. filter() must come before the pipe operator

    5. filter() can’t compare against character strings

  4. (Predict) How many columns does the result of leaf_df %>% select(-mass_g, -thickness_mm) have, if leaf_df starts with 6 columns?

    1. 6

    2. 0

    3. 2

    4. 4

    5. 8

  5. (MC) leaf_df %>% select(shade, ends_with("_mm")) keeps:

    1. Every column except shade

    2. Only rows measured in millimeters

    3. Only mass_g and paper_mass_g

    4. Every row where shade is missing

    5. shade plus every column whose name ends in "_mm"

mutate() and arrange() — new columns and sorting

  1. (MC) leaf_df %>% mutate(mass_mg = mass_g * 1000):

    1. Adds a new mass_mg column and keeps all the existing columns

    2. Replaces leaf_df with just the new column

    3. Deletes mass_g

    4. Only works inside summarize()

    5. Sorts the rows by mass_g

  2. (Fix) The student expected size_class to appear when they later check leaf_df, but it isn’t there. Why?

    leaf_df %>%
  mutate(size_class = if_else(mass_g > 0.5, "large", "small"))

names(leaf_df)

    1. mutate() is broken

    2. if_else() cannot create text values

    3. You need group_by() before mutate()

    4. The result of mutate() was never assigned back to leaf_df (e.g. leaf_df <- leaf_df %>% mutate(...))

    5. size_class needs to be created with select(), not mutate()

    3. The heaviest leaf comes first

    4. Rows are grouped by shade first

    5. The lightest leaf comes first

    True / False

The pipe and chaining verbs together

  1. (Predict) ★ Reading top to bottom, what does this pipeline do?

    clean_df <- leaf_df %>%
  filter(mass_g > 0) %>%
  select(shade, mass_g, thickness_mm) %>%
  arrange(shade, desc(mass_g))

    1. Groups by shade and computes a mean

    2. Adds three new columns, then deletes rows with negative values

    3. Sorts first, then filters, then renames the columns

    4. Keeps rows with mass_g > 0, keeps three columns, then sorts by shade and (within shade) by mass_g high to low

    5. Removes the shade column entirely before sorting

  2. (T/F) The pipe %>% takes the result on its left and feeds it in as the first argument of the function on its right.

    True / False

  3. (MC) The main advantage of chaining filter() %>% select() %>% arrange() with the pipe, instead of nesting the same calls inside each other, is that:

    1. It runs faster on large data sets

    2. It automatically fixes typos in column names

    3. It removes the need for library(dplyr)

    4. It converts all columns to character type

    5. The steps read top to bottom in the order they happen, which is easier to follow
