Why Quarto, and the parts of a .qmd

1. (MC) Every .qmd file is built from three kinds of content. Which list is correct?

a. YAML front matter, Markdown text, code chunks
b. Title, abstract, references
c. Console, Script, Environment
d. Data, figures, tables

2. (MC) The YAML front matter at the top of a .qmd file is best described as:

a. A code chunk that runs first
b. The “recipe” — settings like title, author, and output format
c. Where you write your discussion section
d. Decoration with no effect on rendering

3. (T/F) A Quarto report is more reproducible than a script whose numbers are copy-pasted into Word by hand, because it recomputes every number and figure from the data on each render.

True / False

4. (T/F) A number typed by hand into your prose stays correct automatically when the underlying data changes.

True / False

YAML

5. (T/F) YAML is space-sensitive: a stray leading space or a mix of tabs and spaces can stop the file from rendering.

True / False

6. (Fix) This YAML fails to parse. What is wrong?

---
title: "Leaf Report"
author: "Your Name"
 date: today
format: docx
---

a. date: today has a stray leading space, breaking the alignment of the top-level keys
b. title cannot have quotes
c. format: docx must be format: word
d. author must come before title

7. (Fix) This YAML line causes a parse error: format:docx. What is wrong?

a. docx should be capitalized
b. There must be a space after the colon: format: docx
c. format is not a real YAML key
d. It needs quotes: format:"docx"

8. (Predict) Given this YAML, what will the Word document have?

format:
  docx:
    toc: true
    number-sections: true

a. A table of contents and numbered section headings
b. No table of contents, unnumbered sections
c. A PowerPoint file
d. Nothing changes from the default

9. (Predict) Given this YAML, how many output files does one Render produce?

format:
  docx: default
  html: default
  pptx: default

a. 1 b. 2 c. 3 d. it errors — you can only list one

10. (T/F) You can produce a Word document, a web page, and slides from one .qmd by listing docx, html, and pptx under format: and rendering once.

True / False

Markdown

11. (MC) In Markdown, what does a single # at the start of a line do?

a. Comments out the line
b. Makes a top-level heading
c. Makes a bullet point
d. Makes the text bold

12. (Predict) How does this Markdown render?

# Introduction

We measured leaf mass on the **sunny** and **shady** sides.

- Null hypothesis: no difference
- Alternate hypothesis: sides differ

a. All four lines as plain text
b. “Introduction” as a big heading, “sunny”/“shady” bold, and the last two lines as bullets
c. Everything as a bulleted list
d. “Introduction” as a bullet and the rest as headings

13. (MC) Surrounding a word with **double asterisks** makes it:

a. italic b. bold c. a heading d. code

Code chunks and chunk options

14. (MC) Which fence correctly opens a chunk that runs as R code?

a. ### {r}
b. ```{r}
c. [[r]]
d. <r>

15. (MC) echo and eval control, respectively:

a. Whether the code is shown; whether the code runs
b. Whether the code runs; whether the code is shown
c. The font size; the figure size
d. The output format; the file name

16. (Predict) A chunk has echo: false and eval: true. In the rendered document you see:

a. The code only
b. The result only
c. Both the code and the result
d. Neither

17. (Predict) A chunk has echo: true and eval: false. In the rendered document you see:

a. The code only (nothing runs, so no output)
b. The result only
c. Both
d. Neither

18. (Predict) This chunk has echo: false and eval: true:

#| echo: false
#| eval: true
mean(c(4, 3, 5, 8))

What appears in the rendered document?

a. The code and the number 5
b. Just the number 5
c. Just the code
d. An error

19. (T/F) echo: true, eval: false is a useful combination for a student workbook: learners see the exact code without it running.

True / False

20. (MC) A situation where you would set echo: false in a chunk:

a. A polished lab report for a reader who wants results, not code
b. A teaching handout where students must see the code
c. Any time the code has an error
d. Never — echo should always be true

Inline code and cross-references

21. (MC) “Inline code” means:

a. A whole code chunk on its own line
b. A small live R expression dropped into a sentence so the value updates on every render
c. Code that has been commented out
d. Code written in the Console instead of the document

22. (Predict) An earlier chunk computed mean_shady <- 7.8. You write “Shady-side leaves averaged” then an inline code expression that calls mean_shady, then ” g.” When the document renders, the sentence reads:

a. Shady-side leaves averaged mean_shady g.
b. Shady-side leaves averaged 7.8 g.
c. Shady-side leaves averaged (the raw expression text, unevaluated) g.
d. An error

23. (T/F) ★ For a figure cross-reference like @fig-leaf-plot to work, the chunk’s label must begin with fig-.

True / False

Troubleshooting a render

24. (T/F) Quarto runs the code chunks top to bottom in a fresh session, so a chunk that loads your libraries and data must appear above any chunk that uses them.

True / False

25. (T/F) Two code chunks in the same document are allowed to share the same label.

True / False

26. (Fix) Render fails with Duplicate chunk label 'plot'. Two chunks are labeled #| label: plot. The fix is:

a. Delete one of the chunks
b. Give each chunk a unique label, e.g. plot-box and plot-means
c. Remove all labels from the document
d. Change the format to html

27. (Fix) A chunk errors with object 'leaf_df' not found. Most likely cause?

a. leaf_df is spelled wrong everywhere
b. The chunk that reads in leaf_df is missing or is below this chunk
c. Quarto cannot use data frames
d. You must render to Word first

28. (Fix) A chunk errors with could not find function "%>%". The fix is:

a. Add library(tidyverse) in a chunk near the top, before any chunk that uses the pipe
b. Replace every %>% with a comma
c. Render to html instead of docx
d. Rename the chunk

29. (Fix) An inline value renders literally as the raw expression text instead of a number. The prose refers to maen_shady, but the earlier chunk created mean_shady. What is wrong?

a. Inline code cannot use objects from other chunks
b. The object name is misspelled — maen_shady should be mean_shady
c. You must render to PowerPoint
d. The chunk needs echo: true

30. (Fix) ★ Rendering stops partway through with no clear line number. A student’s R chunk opens with the fence line ```{r summary-table} and has three lines of code, but the student never typed the closing ``` fence line after the code. The problem is:

a. The closing ``` fence is missing, so Quarto treats the rest of the file as still inside the chunk
b. group_by() must come after summarize()
c. The chunk label has a dash in it
d. na.rm = TRUE is invalid
