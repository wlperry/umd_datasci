Spatial data and coordinate systems

1. (T/F) An sf object is basically a normal data frame with an extra geometry column.

True / False

2. (MC) Plain longitude/latitude coordinates (what GPS and most CSVs use) correspond to which CRS?

a. EPSG:3857 b. EPSG:4326 c. EPSG:5070 d. There is no CRS for lat/long

3. (MC) The CRS (coordinate reference system) of a spatial dataset is:

a. The rulebook that says what the coordinate numbers actually mean on the Earth
b. The number of rows in the data
c. The color scale of the map
d. The file format

4. (MC) A “choropleth” is:

a. A single location, like one sighting
b. A map that shades areas by a value
c. The rulebook for what coordinate numbers mean
d. An area outline, like a state

5. (T/F) ★ coord_sf(crs = 5070) reprojects the map for display only — it does not change your underlying data.

True / False

Making points spatial

6. (MC) Which call turns bigfoot_df into an sf object with CRS 4326?

a. st_as_sf(bigfoot_df, coords = c("longitude", "latitude"), crs = 4326)
b. st_as_sf(bigfoot_df, coords = c("latitude", "longitude"), crs = 4326)
c. as_sf(bigfoot_df, lat, long)
d. st_as_sf(bigfoot_df)

7. (Fix) A student’s points land in the wrong hemisphere. Their call is st_as_sf(coords = c("latitude", "longitude"), crs = 4326). What is wrong?

a. coords must be x first, then y: c("longitude", "latitude")
b. crs should be 3857
c. st_as_sf() cannot take a crs argument
d. Nothing — the points are fine

8. (Fix) st_as_sf() errors because a few latitude values are NA. What must you do first?

a. filter(!is.na(latitude), !is.na(longitude)) before st_as_sf()
b. Replace every NA with 0
c. Change the CRS
d. Use pivot_longer() first

9. (T/F) Latitude is the y-coordinate and longitude is the x-coordinate.

True / False

Drawing maps and choropleths

10. (MC) To draw states_sf as a grey basemap with bigfoot_sf points on top, the layer order is:

a. geom_sf(data = states_sf, ...) first, then geom_sf(data = bigfoot_sf, ...)
b. Points first, then the basemap on top
c. Order does not matter for maps
d. Both must be in a single geom_sf() call

11. (MC) A per-state choropleth of counts is built by:

a. Plotting points only
b. Counting per state, joining those counts to the state polygons, and filling by the count
c. Using pivot_wider() on the coordinates
d. Changing the CRS to 3857

12. (Predict) You join sighting counts to states_sf but the whole choropleth is grey with all-NA fills. The report state values are "Washington"; the map’s are "washington". Cause and fix?

a. Key mismatch from letter case; fix with str_to_lower() so both keys match
b. The CRS is wrong; change to 5070
c. geom_sf() is broken; use geom_polygon()
d. There are too many states

13. (Predict) ★ A choropleth of raw sighting counts (not per-capita) mostly ends up highlighting:

a. The states where the phenomenon is genuinely most common
b. The most populous states, because more people means more reports
c. The states with the smallest area
d. Nothing — counts cannot be mapped

14. (Fix) geom_sf(data = bigfoot_df) errors. bigfoot_df is a plain data frame with longitude/latitude columns. What is missing?

a. Convert it to an sf object first with st_as_sf(..., coords = c("longitude", "latitude"), crs = 4326)
b. geom_sf() should be geom_point()
c. You need library(ggplot2)
d. Nothing — this works
