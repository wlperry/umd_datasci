Data: leaf_df has one row per leaf, columns shade ("sunny"/"shady"), mass_g, petiole_mm, thickness_mm, paper_mass_g. Some paper_mass_g values are missing (NA).

The pipe %>%

1. (MC) What does the pipe %>% do?

a. Assigns a value to a variable
b. Takes the result on its left and feeds it in as the first argument on its right
c. Compares two values for equality
d. Loads a package

2. (T/F) Writing one pipeline with %>% runs the steps top to bottom, which is easier to read than nesting the same functions inside each other.

True / False

3. (Fix) mass_g %>% mean(leaf_df) errors. What is the correct call?

a. leaf_df %>% pull(mass_g) %>% mean(na.rm = TRUE)
b. mean(leaf_df) %>% mass_g
c. leaf_df %>% mean(mass_g)
d. mass_g %>% leaf_df %>% mean()

11. (Predict) leaf_df has 24 rows (12 sunny, 12 shady). Roughly how many rows does leaf_df %>% filter(shade == "sunny") return?

a. 0 b. 12 c. 24 d. 48

12. (Predict) Reading top to bottom, what does this pipeline do?

clean_df <- leaf_df %>%
  filter(mass_g > 0) %>%
  select(shade, mass_g, thickness_mm) %>%
  arrange(shade, desc(mass_g))

a. Adds three new columns, then deletes rows
b. Keeps rows with mass_g > 0, keeps three columns, then sorts by shade and (within shade) by mass_g high to low
c. Groups by shade and computes a mean
d. Sorts first, then filters, then renames

= vs == and case sensitivity

13. (MC) Inside filter(), which symbol tests whether two things are equal?

a. = b. == c. <- d. %>%

14. (Fix) This throws We detected a named input. What is the fix?

leaf_df %>% filter(shade = "sunny")

a. filter(shade == "sunny") — use == to compare, not =
b. filter("sunny" = shade)
c. filter(shade <- "sunny")
d. filter(shade = "sunny", strict = FALSE)

15. (Fix) The student typed "Sunny" but got zero rows even though sunny leaves exist. Why?

leaf_df %>% filter(shade == "Sunny")

a. filter() only works on numbers
b. R is case-sensitive; the data stores "sunny" (lowercase)
c. You need quotes around shade
d. filter() must come before the pipe

16. (T/F) filter(shade == "Sunny") and filter(shade == "sunny") return the same rows.

True / False

Missing values (NA)

17. (MC) x has five values, two of which are NA. Which counts only the real (non-missing) values?

a. length(x)
b. sum(!is.na(x))
c. nrow(x)
d. mean(x)

18. (T/F) mean(x) returns NA if even one value in x is NA, unless you add na.rm = TRUE.

True / False

19. (Predict) What does the second line print?

x <- c(4, 3, NA, 7, NA)
sum(!is.na(x))

a. 2 b. 3 c. 5 d. NA

20. (Fix) This returns NA with no error message. Why, and what is the fix?

mean(leaf_df$paper_mass_g)

a. paper_mass_g has missing values; add na.rm = TRUE
b. mean() does not work on data frames
c. You forgot library(dplyr)
d. The column name is misspelled

21. (Fix) ★ This SE line is silently wrong when sunny_mass contains NA values. What is the bug?

se_sunny <- sd(sunny_mass, na.rm = TRUE) / sqrt(length(sunny_mass))

a. sd() should be var()
b. length(sunny_mass) counts the NA values too; use sum(!is.na(sunny_mass))
c. sqrt() should be ^2
d. Nothing is wrong

Mean, median, SD, SE

22. (Predict) Sunny masses are 5, 6, 7, 8, 50. What are the mean and the median?

a. mean = 7, median = 15.2
b. mean = 15.2, median = 7
c. mean = 7, median = 7
d. mean = 50, median = 8

23. (MC) For the data in Q22 (5, 6, 7, 8, 50), which is the “fairer” summary of a typical value?

a. The mean, because it uses every value
b. The median, because the single large value (50) drags the mean away from the bulk of the data
c. They are equally fair here
d. Neither — you must remove all five values

24. (T/F) SD describes how spread out the individual data points are; SE describes how precisely you have estimated the group mean.

True / False

25. (T/F) Because SE = SD / √n, collecting more leaves per group makes the SE smaller.

True / False

26. (T/F) ★ If a group’s mean is much larger than its median, that usually points to a right-skewed distribution — a few unusually large values pulling the mean up.

True / False

Common mistakes

30. (Fix) The student expected size_class to appear when they check leaf_df afterward, but it is not there. Why?

leaf_df %>%
  mutate(size_class = if_else(mass_g > 0.5, "large", "small"))

names(leaf_df)

a. mutate() is broken
b. The result of mutate() was never assigned back (e.g. leaf_df <- leaf_df %>% mutate(...))
c. if_else() cannot make text
d. You need group_by() first

31. (T/F) A wrangling step like leaf_df %>% filter(mass_g > 0.5) changes leaf_df itself, even if you do not assign the result to anything.

True / False

32. (Fix) ★ The student wanted only mass_g and thickness_mm, but this keeps every column except those two. What happened?

leaf_df %>% select(-mass_g, -thickness_mm)

a. The minus signs tell select() to drop those columns; remove them: select(mass_g, thickness_mm)
b. select() needs quotes: select("-mass_g", "-thickness_mm")
c. select() should be filter()
d. Nothing is wrong — this keeps the two columns
