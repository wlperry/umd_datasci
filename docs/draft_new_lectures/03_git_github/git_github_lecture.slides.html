Note

✅ Key idea from Lecture 02

You now have a project folder on your computer. Today we make sure that folder can never be permanently lost, and that anyone — including future-you — can see exactly how it changed over time.

Goals for Today

Two new tools, one purpose — a safety net for your work:

  • Git — a program on your computer that saves numbered snapshots of a folder over time
  • GitHub — a website that stores a copy of those snapshots online

By the end of today you will have:

  1. Git installed on your laptop
  2. A free GitHub account
  3. GitHub Desktop installed (the point-and-click way to use Git)
  4. Your first repository, with one saved snapshot (“commit”) pushed online

Tip

🖐 Try it yourself

No command line required today. Everything is done by clicking buttons in GitHub Desktop — you can learn the typed commands later, once these ideas make sense.

Today’s new vocabulary:

Word Plain-English meaning
Repository (“repo”) A project folder that Git is watching
Commit A saved, labeled snapshot of your folder
Push Send your snapshots to GitHub online
Pull Get any new snapshots from GitHub onto your computer

Reference: GitHub Desktop docs

Why Bother? (Before We Install Anything)

  • Your laptop will eventually have a problem — spilled coffee, a crashed hard drive, an update gone wrong. Deadlines do not wait for that to not happen to you.
  • “final_v2_ACTUALLYFINAL_use_this_one.R” is a filename every scientist has typed. Git replaces that whole mess with one real history.
  • Every homework, activity, and your final project can live in a repo. If you ever lose your laptop, your work is still safely on GitHub.

Note

✅ Key idea

Git does not replace saving your file (Cmd/Ctrl + S). It adds a second, permanent save button — one that keeps every past version, not just the latest one.

🧩 Part 1 of 4 · Install Git

Tip

🖐 After this part: Activity Part 1 — confirm Git is installed.

Installing Git — macOS

  1. Open the app called Terminal (press Cmd + Space, type “Terminal,” press Enter)
  2. Type exactly: git --version and press Enter
  3. If a version number appears (like git version 2.39.2) — you already have Git. Skip to Part 2.
  4. If a box pops up asking to install “command line developer tools” — click Install, wait for it to finish (a few minutes), then repeat step 2 to confirm

Warning

⚠️ Watch out!

Do not search the web and download some random “Git for Mac” installer. macOS already knows how to install the real thing the moment you ask for git --version — that popup is the official installer.

Installing Git — Windows

  1. Go to git-scm.com/download/win in your browser
  2. Click the link that says “64-bit Git for Windows Setup”
  3. Open the downloaded file and click Next on every screen — the default options are all fine. Do not change anything unless you know why.
  4. When it finishes, open the Start Menu, type “Git Bash,” and open it
  5. Type exactly: git --version and press Enter — a version number should appear

Tip

“Git Bash” vs. plain Windows

The installer adds a program called Git Bash — a small black window where you can type commands. You will barely use it today, but it’s how you’ll later confirm Git is really installed and working.

🧩 Part 2 of 4 · Create Your GitHub Account

Tip

🖐 After this part: Activity Part 2 — create your account.

Sign Up at github.com

  1. Go to github.com in your browser
  2. Click Sign up
  3. Use an email you check often — your school email is fine, or a personal one
  4. Choose a username you wouldn’t mind a future employer seeing — future you will use this professionally
  5. Verify your email when GitHub asks

Note

✅ Key idea

GitHub is free for what we’re doing. You are not entering payment information anywhere in this process — if a screen asks for a credit card, stop and ask before continuing.

🧩 Part 3 of 4 · Install GitHub Desktop

Tip

🖐 After this part: Activity Part 3 — install and sign in.

GitHub Desktop — Both Mac and Windows

  1. Go to desktop.github.com
  2. Click the big Download button — it detects Mac vs. Windows automatically
  3. Open the downloaded file and install it like any other app (drag to Applications on Mac; run the installer on Windows)
  4. Open GitHub Desktop
  5. Click Sign in to GitHub.com and log in with the account you just made
  6. It will ask “Where are your repositories?” — for now, accept the default location it suggests

Tip

Why a whole separate app?

GitHub Desktop turns “commit” and “push” into buttons you click, instead of commands you type. You can graduate to the command line or to R’s built-in Git tools later — this is the on-ramp, not a permanent training-wheel you’ll be stuck with.

🧩 Part 4 of 4 · Your First Repository

Tip

🖐 After this part: Activity Parts 4–7 — create, commit, and push.

Create a New Repository

  1. In GitHub Desktop, click File → New Repository
  2. Name: something clear, like datasci-coursework
  3. Local path: click Choose… and pick a folder you will remember — Desktop or Documents, not a folder inside OneDrive or Google Drive (see the File System lecture for why)
  4. Check the box Initialize this repository with a README
  5. Click Create Repository

Note

✅ Key idea

A repository is just a normal folder on your computer — you can open it in Finder or File Explorer like any other folder. The only difference is that Git is quietly watching everything that happens inside it.

Make a Change and Commit It

  1. Open the repository folder (GitHub Desktop → Show in Finder / Explorer)
  2. Open README.md in any text editor and add one sentence, like “This is my data science coursework repo.”
  3. Save the file
  4. Switch back to GitHub Desktop — your change appears automatically in the left panel
  5. At the bottom left, type a short summary (e.g. “Add a note to README”) in the box
  6. Click the blue Commit to main button

Tip

Writing good commit summaries

Write what you did, in plain English, present tense: “Add leaf cleaning script,” not “stuff” or “updates.” Six months from now, this is the only clue you’ll have about what changed and why.

Push — Send It to GitHub Online

  1. After committing, click the button at the top that now says Push origin
  2. Wait a few seconds for the upload
  3. Click View on GitHub (or go to github.com and open your repository)
  4. Confirm you can see your README change on the website, not just on your laptop

Note

✅ Key idea

Commit = save a snapshot on your computer. Push = copy that snapshot to GitHub online. You need both — a commit that is never pushed only protects you if GitHub Desktop can see your laptop, not if your laptop is lost or damaged.

What We Learned Today

  • Git = a program that saves numbered snapshots of a folder on your computer
  • GitHub = a website that stores a copy of those snapshots online
  • Repository = a normal folder Git is watching
  • Commit = a saved, labeled snapshot (“save button #2”)
  • Push = send your commits to GitHub online
  • GitHub Desktop turns all of this into buttons — no typed commands needed yet
