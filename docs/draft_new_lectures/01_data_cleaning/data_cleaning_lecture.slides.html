Goals for Today

The real-world problem:

  • Field data entered by hand is never perfect
  • Typos, inconsistent capitalization, stray spaces
  • Missing values coded a dozen different ways
  • Numbers accidentally typed as text
  • Rows entered twice by mistake

What we’ll learn:

  • How to see messiness with skim() and count()
  • Fix text inconsistency: str_trim(), str_to_lower()
  • Fix fake NA codes: na = c(...), na_if()
  • Fix numbers-as-text: parse_number()
  • Find and remove duplicates: distinct()
  • Flag, don’t silently delete, suspicious values

📖 R4DS §18 — Missing Values

Column Names — clean_names()

# janitor::clean_names() standardizes column names ----
names(leaf_raw_df)
[1] "id"             "tree_id"        "side"           "weight_g"      
[5] "height_cm"      "width_cm"       "date_collected" "notes"         
leaf_raw_df <- leaf_raw_df %>% clean_names()

names(leaf_raw_df)
[1] "id"             "tree_id"        "side"           "weight_g"      
[5] "height_cm"      "width_cm"       "date_collected" "notes"
  • Forces lowercase, snake_case, no spaces or symbols
  • Our names already happened to be tidy — but real spreadsheets rarely are ("Weight (g)", "Tree ID", "% Cover")
  • Always run this first — it costs nothing and prevents backtick nightmares like `Tree ID`

Rule #2 — Count Categories, Never Assume

Note

🔮 Predict first: How many distinct values do you think side has? There are only two real sides — sunny and shady. Guess the number count() will show, then run it.

# count() shows every distinct value AND its frequency -
leaf_raw_df %>% count(side)
# A tibble: 6 × 2
  side      n
  <chr> <int>
1 SHADY     2
2 SUNNY     1
3 Shady     2
4 Sunny     3
5 shady     6
6 sunny     6

Warning

⚠️ Watch out!

"Sunny", "sunny ", "sunny", " SHADY", "Shady" are all different strings to R — capitalization and whitespace count. Two categories became eight.

count() is the single fastest way to catch a messy categorical column — run it on every <chr> column before you trust it.

🧩 Chunk 2 of 4 · Fixing Text — Case & Whitespace

We will cover: str_trim(), str_to_lower(), and rebuilding a clean side column.

Tip

🖐 After this chunk: Activity Part 3.

str_trim() — Killing Invisible Spaces

# str_trim() removes leading/trailing whitespace -------
x <- c("sunny", " sunny", "sunny ", "  sunny  ")
x
[1] "sunny"     " sunny"    "sunny "    "  sunny  "
str_trim(x)
[1] "sunny" "sunny" "sunny" "sunny"
  • Whitespace is invisible in a printed value — you cannot see the bug by eye
  • " sunny" and "sunny" look identical in head() but are different strings
  • str_trim() removes spaces from both ends

str_to_lower() — Killing Case Differences

# str_to_lower() forces everything to lowercase --------
y <- c("Sunny", "SUNNY", "sunny", "SHADY", "Shady")
str_to_lower(y)
[1] "sunny" "sunny" "sunny" "shady" "shady"
  • Combine both fixes in one mutate() step
  • Order does not matter here, but always do this before you count() or group_by()

📖 R4DS §17 — Strings

Fixing side — Putting It Together

Note

🔮 Predict first: After trimming and lowercasing, how many distinct values should count(side) show?

# Trim whitespace and force lowercase in one mutate ----
leaf_clean_df <- leaf_raw_df %>%
  mutate(side = str_trim(side)) %>%
  mutate(side = str_to_lower(side))

leaf_clean_df %>% count(side)
# A tibble: 2 × 2
  side      n
  <chr> <int>
1 shady    10
2 sunny    10

Note

✅ Key idea

Two clean categories, exactly as the field notebook intended. This single mutate() pair is one of the most common lines you will ever write in R.

Warning

⚠️ Watch out!

Real “missing” shows up as NA, "N/A", -999, 999, and true blank cells — all in the same column. R only recognizes a true blank or the literal text NA as missing by default. -999 and 999 look like perfectly valid numbers to R.

Fixing It at the Source — read_csv(na = ...)

# Tell read_csv about every missing-value code you saw -
leaf_raw_df <- read_csv(
  "data/messy_leaf_data.csv",
  na = c("", "NA", "N/A", "-999", "999")
)

leaf_raw_df %>% count(is.na(weight_g))
# A tibble: 2 × 2
  `is.na(weight_g)`     n
  <lgl>             <int>
1 FALSE                17
2 TRUE                  3
  • Best practice: fix missing-value codes at read_csv() time, before anything else
  • You must first count() a column to discover what its missing codes even are — R cannot guess for you
  • -999 and 999 were both used in the same column — inspect every numeric-looking column this way

na_if() — Fixing It After the Fact

# na_if() converts a specific value to a true NA -------
z <- c(5.2, 4.8, -999, 7.9, 999)

na_if(z, -999) %>% na_if(999)
[1] 5.2 4.8  NA 7.9  NA

Tip

Use na_if() inside mutate() when you discover a sentinel value after loading, or when only one column (not the whole file) uses that code.

📖 R4DS §18

Finding Duplicate Rows — distinct() and duplicated()

# Check for exact duplicate rows -----------------------
sum(duplicated(leaf_raw_df))
[1] 0
leaf_raw_df %>%
  filter(duplicated(leaf_raw_df) | duplicated(leaf_raw_df, fromLast = TRUE))
# A tibble: 0 × 8
# ℹ 8 variables: id <dbl>, tree_id <chr>, side <chr>, weight_g <chr>,
#   height_cm <dbl>, width_cm <dbl>, date_collected <chr>, notes <chr>
# distinct() keeps only the first copy of each row -----
leaf_clean_df <- leaf_raw_df %>% distinct()

nrow(leaf_raw_df)
[1] 20
nrow(leaf_clean_df)
[1] 20

Note

✅ Key idea

duplicated() flags rows so you can look at them before deleting — always inspect first. distinct() then removes exact repeats, keeping one copy.

What We Learned Today

  • See the mess first: glimpse(), skim(), count() on every <chr> column
  • Column names: janitor::clean_names()
  • Text inconsistency: str_trim() + str_to_lower()
  • Fake missing codes: na = c(...) at read_csv(), or na_if() after
  • Numbers trapped in text: parse_number()
  • Duplicate rows: duplicated() to inspect, distinct() to remove
  • Suspicious values: flag with mutate(), never delete silently
