Folders, paths, and why OneDrive and Google Drive break things

Note

Every single thing we do this semester — loading data, saving a plot, submitting homework, using Git — depends on one skill: knowing exactly where a file lives on your computer. This lecture has zero code. It is the most important 50 minutes of the term.

Goals for Today

  • See your computer’s real folder structure, not just app icons
  • Turn on file extensions so you can see what kind of file something actually is

  • Learn the difference between a file that is really on your computer and one that only looks like it is
  • Understand why OneDrive and Google Drive cause real, repeatable problems for coding — and how to avoid them

Tip

🖐 Try it yourself

By the end, you will create one folder that you know, with total confidence, is a real folder on your local hard drive — and you’ll use that same folder all semester.

Today’s new vocabulary:

Word Plain-English meaning
File extension The letters after the dot: .csv, .docx, .R
Path The full address of a file, folder by folder
Local Actually stored on this computer’s hard drive
Cloud-only A placeholder — the real file lives on the internet

🧩 Part 1 of 4 · Seeing What’s Really There

Turn On File Extensions — macOS

  1. Open Finder
  2. Click Finder → Settings (or Preferences on older macOS)
  3. Click the Advanced tab
  4. Check “Show all filename extensions”

Warning

⚠️ Watch out!

Without this on, leaf_data.csv and leaf_data.xlsx and leaf_data.docx all just look like “leaf_data” with no way to tell them apart except a tiny icon. Turn this on today, permanently.

Turn On File Extensions — Windows

  1. Open File Explorer (folder icon in the taskbar)
  2. Click the View tab at the top
  3. Click Show, then check File name extensions
    (Older Windows: View → Options → View tab → uncheck “Hide extensions for known file types”)

Tip

Do this once, right now, on your own laptop — not later “when it matters.” It matters starting with the very first homework.

What a File Extension Actually Tells You

Extension What it is
.csv Plain data table (what R usually wants)
.xlsx Excel workbook
.docx Word document
.R An R script — plain text with R code
.qmd A Quarto document (code + writing)
.pdf A fixed, non-editable document

Note

✅ Key idea

The extension is not decoration — it tells your computer, and R, which program should open the file and how to read it. A .csv that got accidentally renamed .csv.docx will fail to load, and the extension is the only clue why.

🧩 Part 2 of 4 · Folders and Paths

Your Computer Is a Tree of Folders

Every file lives inside a folder, which lives inside another folder, all the way back to the very top of your hard drive.

A path is just that chain of folder names, written out:

Mac:      /Users/yourname/Documents/datasci-coursework/data/leaf.csv
Windows:  C:\Users\yourname\Documents\datasci-coursework\data\leaf.csv

Read it left to right: hard drive → Users → your account → Documents → your course folder → data → the file.

Tip

Mac vs. Windows paths

Mac and Linux use forward slashes /. Windows uses backslashes \. R almost always wants forward slashes /, even on Windows — R will tell you if you get this wrong.

Finding a File’s Exact Path

Mac: right-click the file in Finder, hold Option, and choose “Copy [filename] as Pathname”

Windows: hold Shift, right-click the file, choose “Copy as path”

Note

✅ Key idea

If you are ever unsure why R says “cannot find file,” the fix is almost always: get the real path this way, and compare it — character by character — to what you typed into read_csv().

Absolute vs. Relative Paths

  • An absolute path starts from the very top of the drive: /Users/yourname/Documents/...
  • A relative path starts from wherever your R Project currently is: data/leaf.csv

In this course, we always use relative paths inside an R Project — that’s why we set up a project folder in Lecture 02. It means your code works identically on your laptop and your instructor’s.

Warning

⚠️ Watch out!

An absolute path like /Users/wlperry/Desktop/leaf.csv will never work on anyone else’s computer — including your own after you rename your user account or get a new laptop. This is exactly the kind of thing that breaks “reproducibility.”

🧩 Part 3 of 4 · The Cloud-Storage Trap

Real File vs. Cloud-Only Placeholder

OneDrive and Google Drive can show a file in a folder without the file actually being on your computer. Instead, a tiny placeholder “promises” to download it the moment something opens it.

Look for a small icon next to the filename:

Icon meaning What it means
Cloud outline Not actually here yet — internet required
Solid checkmark Truly downloaded and on this computer

Warning

⚠️ Why this breaks R specifically

R does not politely wait for a cloud download the way opening a document does. It fails immediately with “cannot find file” or “file not found” — even though you can clearly see the file sitting right there in the folder.

Fixing It — Force Files to Actually Be Local

OneDrive (Mac or Windows): right-click the folder → “Always keep on this device”

Google Drive: right-click the folder in Google Drive for Desktop → “Available offline”

Wait for the sync icon to change from a cloud to a checkmark before you trust that R can see it.

Tip

Simplest fix of all

For this course, keep your project folder somewhere that is never synced at all — a Documents folder on a computer with OneDrive/Google Drive turned off for that location, or a completely separate local folder like Documents/datasci-coursework outside any synced path.

Our Class Rule for Where Files Live

  1. Make one folder for this entire course — e.g. datasci-coursework
  2. Put it somewhere simple: Desktop, or Documents
  3. Confirm it is not inside a folder with a cloud icon anywhere in its path
  4. This is the same folder you turned into a Git repository, if you’ve done that lecture
  5. Everything for this class lives inside it, in the data/, figures/, scripts/ structure from Lecture 02

Note

✅ Key idea

One known folder, checked once, used all semester, beats a scattered mess of Desktop icons, Downloads-folder clutter, and mystery cloud files every single time.

🧩 Part 4 of 4 · Common Traps

Where Files Secretly Hide

  • Downloads folder — browsers save here by default; files pile up unsorted for years
  • Desktop — technically a real folder (~/Desktop), but on some setups Desktop itself is silently synced to iCloud or OneDrive
  • “Recent” or “Quick access” views — these are shortcuts to files, not the files’ real locations; don’t trust the folder they appear to be in
  • Two files with the same name in different folders — R will load whichever path you actually typed, which might not be the one you meant

Warning

⚠️ Watch out!

If you’re on a Mac and Desktop shows a cloud icon or the phrase “Desktop & Documents Folders” appears anywhere in System Settings → Apple ID → iCloud, your Desktop is being synced — treat it the same as OneDrive/Google Drive above.

What We Learned Today

  • File extensions are always visible now, on both Mac and Windows
  • A path is the full folder-by-folder address of a file
  • Relative paths inside an R Project are why our code works on any computer
  • A cloud icon means a file is not actually here yet — R will fail to see it
  • OneDrive and Google Drive need “always keep on this device” / “available offline” turned on for anything R needs to read
  • You now have one known, local, unsynced folder for this entire course
